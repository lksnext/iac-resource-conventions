# Release Notes — v0.1.0-alpha.0 (draft)

> **Status:** Draft. This is not yet a published release — no package has been published to
> GitHub Packages and no Git tag has been created for this version. See
> [`IMPLEMENTATION.md#release-readiness`](../../IMPLEMENTATION.md#release-readiness) for the
> release-readiness work this draft accompanies.

This is the first alpha of `iac-resource-conventions`'s implementation packages:
`@lksnext/iac-conventions-core`, `@lksnext/iac-conventions-catalog`, and
`@lksnext/iac-conventions-cli`, all versioned `0.1.0-alpha.0`.

## What this alpha supports

- **Specification-first model** — naming, tags, labels, metadata, and validation conventions
  are defined once in [`specification/`](../../specification/) (Resource Identity, Governance
  Context, Naming Request, Context Resolution, Resource Definition, Convention Pack, Convention
  Result), currently at Specification v1.2 (additive over the frozen v1.0 baseline; see
  [`specification/README.md#specification-status`](../../specification/README.md#specification-status)).
- **The Reference Evaluator** — a deterministic, platform-independent implementation of Context
  Resolution and Convention Evaluation, exposed as the public `evaluate()` API from
  `@lksnext/iac-conventions-core` (see
  [`packages/core/README.md`](../../packages/core/README.md)).
- **Executable naming** — component ordering, abbreviation, casing, separator joining,
  optional-component omission, and duplicate-reference rejection (Specification v1.1).
- **Executable Resource Definition constraints** — `min_length`/`max_length`,
  `character_constraints`, and Placement Constraint validation (Specification v1.2).
- **A Resource Definition Catalog** — currently four AWS resource types: `aws_s3_bucket`,
  `aws_iam_role`, `aws_lambda_function`, `aws_acm_certificate`, every technical constraint
  sourced from authoritative AWS documentation (see
  [`packages/catalog/README.md`](../../packages/catalog/README.md)).
- **One Convention Pack** — `aws-workload-default` (see
  [`specification/convention-packs/aws-workload-default.md`](../../specification/convention-packs/aws-workload-default.md)).
- **A CLI adapter**, `iac-conventions`, with two commands:
  - `evaluate` — reads a `{ naming_request, evaluation_context }` JSON document from stdin and
    writes the resulting `ConventionResult` as JSON to stdout.
  - `terraform-external` — a thin transport over the same evaluation path, matching
    HashiCorp's `hashicorp/external` provider protocol, so a `data "external"` data source in
    Terraform can consume these conventions today (see
    [`docs/integrations/terraform.md`](../architecture/../integrations/terraform.md) and
    [`examples/terraform/external/`](../../examples/terraform/external/)).

## Known limitations

- **Only four AWS Resource Definitions** — no Azure, Kubernetes, or GitOps catalog entries
  exist yet, and AWS coverage itself is a deliberately small, evidence-backed slice, not broad
  coverage.
- **Only one Convention Pack** — `aws-workload-default`. No per-tenant, per-organization, or
  additional platform packs are shipped.
- **No metadata projection** — tags, labels, and annotations generation is not implemented;
  only naming and Resource Definition constraint validation are executable today.
- **No general normalization, truncation, hashing, or global uniqueness** — an over-length or
  invalid name is reported as a validation failure, never silently truncated, normalized, or
  hashed to fit.
- **No native Terraform, AWS CDK, or Ansible provider/adapter** — Terraform can consume these
  conventions today only through the CLI's `terraform-external` bridge over
  `hashicorp/external`, which HashiCorp itself documents as an "escape hatch," not a
  first-class provider replacement (see
  [`docs/integrations/terraform.md#limitations`](../../docs/integrations/terraform.md#limitations)).
- **The external bridge requires Node.js and the CLI to be available** wherever Terraform runs
  it (see [Node engine decision](../../IMPLEMENTATION.md#release-readiness)); it is not
  guaranteed to work in Terraform Enterprise's remote execution environment.
- **Pre-1.0 compatibility is not guaranteed** — this is an alpha prerelease; public APIs,
  Convention Packs, generated outputs, and CLI contracts may still change before v1.0.0, per
  [Semantic Versioning](https://semver.org/) prerelease semantics.

## Installation (once published)

These packages are published to **GitHub Packages**, not the public npm registry
(`registry.npmjs.org`) and not any private Nexus registry. GitHub Packages requires
authentication to install even a publicly readable package — configure the `@lksnext` scope to
resolve there, and authenticate with a GitHub personal access token that has at least the
`read:packages` scope (or an equivalent CI token):

```bash
echo "@lksnext:registry=https://npm.pkg.github.com" >> ~/.npmrc
echo "//npm.pkg.github.com/:_authToken=<your-github-token>" >> ~/.npmrc

npm install @lksnext/iac-conventions-cli@alpha
iac-conventions --help
```

See [`packages/cli/README.md`](../../packages/cli/README.md) for full usage, and
[`packages/core/README.md`](../../packages/core/README.md) /
[`packages/catalog/README.md`](../../packages/catalog/README.md) for the programmatic APIs.

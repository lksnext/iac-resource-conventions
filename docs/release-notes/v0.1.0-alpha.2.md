# Release Notes — v0.1.0-alpha.2 (draft)

> **Status:** Draft. This is not yet a published release — no package has been published to
> GitHub Packages and no Git tag has been created for this version. See
> [`docs/release-notes/v0.1.0-alpha.1.md`](v0.1.0-alpha.1.md) for the alpha this one follows.

This alpha closes gaps found when the `lamassuiot/lamassu-terraform-modules`
`aws-acm-certificate` module adopted `v0.1.0-alpha.1` through the `terraform-external`
bridge.

## What this alpha changes

### `null` and wrong-typed request fields are rejected instead of crashing

Before this alpha, a known attribute set to JSON `null` (which Terraform's `jsonencode`
emits for an unset optional object attribute) or to a non-string value made both
`evaluate` and `terraform-external` exit with an unhandled `TypeError` from core's
`applyCasing`. The CLI now validates the JSON type of every known request and
Evaluation Context field and reports the first mismatch as a transport failure (exit
`1`, one stderr line naming the field). `null` is rejected rather than treated as
absent, because the Specification's JSON Schemas type these attributes as strings and
express "unset" by omission (see
[`docs/architecture/cli.md#transport-and-domain-validation-boundary`](../architecture/cli.md#transport-and-domain-validation-boundary)).

**Compatibility:** a wrong-typed *object* field (for example, `"overrides": "x"` or
`"functional": null`) was previously ignored and evaluated with exit `0`; it is now a
transport failure. Inputs that crashed before now fail with a clear message. Valid
inputs produce the same output as before.

### Executable tag projection (Specification v1.3)

`outputs.metadata.tags` existed in the Convention Result but was never populated, so the
consumer could not generate the `Project` and `Environment` tags its replaced AWS CDK
project configured. Specification v1.3 adds an optional Convention Pack field,
`tag_projections`, mapping a tag key to a Resource Identity or Governance Context
attribute (see
[`specification/convention-pack.md#tag-projections`](../../specification/convention-pack.md#tag-projections)
and [`specification/README.md#specification-v13-executable-tag-projection`](../../specification/README.md#specification-v13-executable-tag-projection)).
Tag values are the resolved values, without abbreviation or casing; a tag whose
attribute is not resolved is omitted.

- **core** — `evaluate()` projects `tag_projections` into `outputs.metadata.tags`, and
  reports an empty tag key or an unknown source reference as a validation failure. New
  public types: `MetadataSourceReference`, `GovernanceContextAttribute`.
- **catalog** — `aws-workload-default` now projects `Project`
  (`organizational.system`), `Environment` (`deployment.environment`), `Service`
  (`functional.service`), `Component` (`functional.component`), `Owner`
  (`governance.owner`), `ManagedBy` (`governance.managed_by`), and `CostCenter`
  (`governance.cost_center`). The Azure packs project no tags.
- **cli** — `terraform-external` adds a `tags_json` output field (the projected tags,
  JSON-encoded; `"{}"` when none); `result_json` and `evaluate` carry them under
  `outputs.metadata.tags`. See
  [`docs/integrations/terraform.md#consuming-projected-tags`](../integrations/terraform.md#consuming-projected-tags).

**Compatibility:** results under `aws-workload-default` now include
`outputs.metadata.tags` where they had none, which changes generated tags and is
potentially breaking for consumers that compare full results. Generated names and
validation results are unchanged for every request that does not declare an invalid
`tag_projections` entry. `terraform-external` output gains a key, so consumers that
assert the exact key set must add `tags_json`.

### `Name` tag from the generated name

Resource types without a name argument, such as `aws_acm_certificate`, can only carry
their generated name in the AWS `Name` tag, which the consumer copied by hand.
Specification v1.3's metadata source references include `outputs.name`, the generated
name exactly as generated (omitted when no name is generated). A new, optional
Resource Definition field, `accepts_name`, declares that a provider accepts no
caller-supplied name (`aws_acm_certificate` sets `accepts_name: false`), and a tag
projection entry may use the object form
`{ source, only_when_resource_accepts_no_name: true }`. `aws-workload-default` uses
it to project `Name` only for resource types that accept no name, so `Name` never
duplicates a resource's own name and the other tags stay usable as `default_tags`.

**Compatibility:** `aws_acm_certificate` results under `aws-workload-default` gain a
`Name` tag; other resource types do not. New public types: `TagProjection`,
`ConditionalTagProjection`; `ResourceDefinition` gains `accepts_name`.

### `aws_ssm_parameter` Resource Definition

`aws_ssm_parameter` is now in the catalog (previously `Unknown resource_type`), with
constraints cited from the Systems Manager `PutParameter` API reference and Parameter
Store user guide: `min_length: 1`; letters, digits, `_`, `.`, `-`, and `/`; every
letter-case spelling of the reserved `aws` and `ssm` prefixes, with and without a
leading `/`; Region-scoped uniqueness. Under `aws-workload-default` it renders a flat
name, for example `lamassu-dev-dns-validation-aws_ssm_parameter`.

**Limitation:** the 1011-character ARN-relative maximum, the leading-`/` requirement
for hierarchical names, and the fifteen-level depth limit are documented but not
validated. See
[`docs/architecture/resource-definition-catalog.md#hierarchical-names-aws_ssm_parameter`](../architecture/resource-definition-catalog.md#hierarchical-names-aws_ssm_parameter).

**Compatibility:** additive; no existing name, tag, or validation result changes.

### Hierarchical names: naming `prefix` (Specification v1.4) and `aws-ssm-parameter-path`

Specification v1.4 adds an optional Convention Pack field, `prefix`: literal text
prepended verbatim (never cased or abbreviated) to a generated name (see
[`specification/convention-pack.md#prefix-specification-v14`](../../specification/convention-pack.md#prefix-specification-v14)).
The new `aws-ssm-parameter-path` Convention Pack uses `separator: "/"` and
`prefix: "/"` to render the consumer's hierarchical names, for example
`/lamassu/dev/dns-validation/example-com`, with the leaf name supplied as
`deployment.instance`. Every other field matches `aws-workload-default`.

**Compatibility:** additive. Packs without `prefix` generate the same names as before.
